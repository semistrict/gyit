# Search over object storage

Source inspection on 2026-09-21. These are implementation findings and proposed experiments, not performance measurements. Both repositories were cloned with `gh repo clone` into `~/src/`; neither reference checkout was modified.

## SeaSearch

Checkout: `/Users/ramon/src/seasearch`, commit `c914b4cc84f87197c03009bafefc06f3f513700b`.

**This S3 adapter requires local copies of complete index files. It does not meet gat's bounded, on-demand remote-read requirement as written.**

- **Read path:** `S3Backend.Load` checks the local cache, otherwise opens the remote object without a byte range, copies it into a local cache file, and opens that file. `CacheFile` uses `io.Copy` to completion before returning. `LoadReadOnlyData` memory-maps the local file and gives the mapped bytes to the segment reader. Mapping does not imply every page is resident in RAM, but the entire object has already been downloaded to disk. Sources: [S3 Load](/Users/ramon/src/seasearch/pkg/bluge/directory/s3.go:184), [download](/Users/ramon/src/seasearch/pkg/lru_cache/cache_manager.go:192), [mmap](/Users/ramon/src/seasearch/pkg/lru_cache/cache_manager.go:608).
- **Cache bounds:** the default object cache is 10 GB. Eviction checks existing size before admitting a file, without reserving space for the incoming file. Referenced files cannot be evicted; eviction still returns success when they prevent reaching the target. Therefore this is a soft disk-cache target, not a hard memory or disk bound. Sources: [configuration](/Users/ramon/src/seasearch/pkg/config/config.go:86), [eviction](/Users/ramon/src/seasearch/pkg/lru_cache/cache_manager.go:126).
- **Granularity:** index files are named by a hexadecimal numeric ID and kind suffix under the index prefix. Listing filters those keys by kind and sorts descending. Persist writes the complete file locally, then uploads it. Sources: [list](/Users/ramon/src/seasearch/pkg/bluge/directory/s3.go:158), [persist](/Users/ramon/src/seasearch/pkg/bluge/directory/s3.go:207), [naming](/Users/ramon/src/seasearch/pkg/bluge/directory/s3.go:280).
- **Lazy opening is not lazy remote paging:** `SimpleSearcher` delays opening a reader until a query needs it, specifically to avoid opening many readers simultaneously. This delays the whole-file loading described above. Sources: [searcher](/Users/ramon/src/seasearch/pkg/core/searcher.go:13), [reader opening](/Users/ramon/src/seasearch/pkg/core/index_shards.go:309).
- **Publication and independent readers:** directory `Lock` and `Unlock` are no-ops. Persist has no conditional version argument at this layer. The object-key cache is process-local, has no expiry in the inspected implementation, and is invalidated by local writes/removals/copies. This adapter alone is not a cross-instance CAS publication protocol. SeaSearch also has an etcd-backed cluster assignment layer; these findings do not establish that the whole application is unsafe. Sources: [locks](/Users/ramon/src/seasearch/pkg/bluge/directory/s3.go:272), [key cache](/Users/ramon/src/seasearch/pkg/bluge/directory/keycache.go:39), [cluster](/Users/ramon/src/seasearch/pkg/cluster/cluster.go:30).
- **Snapshot retention matters:** reader opening explicitly retries when concurrent writer cleanup removes a listed snapshot. That is different from retaining an arbitrary historical revision for a mounted reader. Source: [retry](/Users/ramon/src/seasearch/pkg/core/index_shards.go:321).
- **Integration is fork-specific:** `go.mod` replaces upstream Bluge, its segment API, and ICE with three forks. The segment API's `Data` internally supports `io.ReaderAt`, but the published constructors at the pinned version accept bytes or `*os.File`, not a general remote reader. A range-backed adapter would require an API extension plus a read-pattern audit, not merely swapping this directory. Sources: [replacements](/Users/ramon/src/seasearch/go.mod:153), [pinned segment API](https://github.com/zincsearch/bluge_segment_api/blob/v1.0.0/data.go).
- **Search semantics:** SeaSearch builds field-oriented analyzed queries and exposes a Bluge regex query. Those interfaces do not establish Git-compatible matching over original lines, punctuation, binary detection, and output ordering. Its regex wrapper even leaves flags as a TODO. Sources: [standard analyzer](/Users/ramon/src/seasearch/pkg/uquery/analysis/analyzer/standard.go:26), [regex wrapper](/Users/ramon/src/seasearch/pkg/uquery/query/regexp.go:28).

## Quickwit

Checkout: `/Users/ramon/src/quickwit`, commit `c02cc1c8a2734d41bf4313365e4e5169b4774100`.

**Quickwit demonstrates real partial reads from S3, but its query warmup does not enforce a small hard memory bound.**

- **Object layout:** a `.split` bundles index files, a file-offset table, and a hotcache containing selected startup data. The offset table and hotcache are adjacent so they can be retrieved together. The source's offset table uses versioned JSON; gat should retain protobuf. Sources: [layout](/Users/ramon/src/quickwit/quickwit/quickwit-directories/src/bundle_directory.rs:34), [builder](/Users/ramon/src/quickwit/quickwit/quickwit-storage/src/split.rs:214).
- **Actual partial I/O:** the search request includes footer offsets. A cold open reads that interval; subsequent virtual-file reads translate into offsets in the containing split. The S3 implementation sends an HTTP Range header. Entire split downloads are not necessary on this path. Sources: [footer read](/Users/ramon/src/quickwit/quickwit/quickwit-search/src/leaf.rs:127), [offset translation](/Users/ramon/src/quickwit/quickwit/quickwit-storage/src/bundle_storage.rs:506), [S3 Range](/Users/ramon/src/quickwit/quickwit/quickwit-storage/src/object_storage/s3_compatible_storage.rs:696).
- **Hotcache construction:** a recording directory captures ranges touched while opening readers and inverted indexes. This is a useful way to discover data that should be colocated for startup, but the builder's filtering is not a global small-cache cap. Source: [hotcache generation](/Users/ramon/src/quickwit/quickwit/quickwit-directories/src/hot_directory.rs:472).
- **Query warmup:** remote reads are asynchronous, while Tantivy search is synchronous. Quickwit first warms the needed postings, dictionaries, positions, and other fields into a per-split byte-range cache created with infinite capacity. It measures actual memory after warmup and adjusts admission accounting; its scheduler explicitly allows temporary overshoot. Sources: [sync-read restriction](/Users/ramon/src/quickwit/quickwit/quickwit-directories/src/storage_directory.rs:50), [warmup](/Users/ramon/src/quickwit/quickwit/quickwit-search/src/leaf.rs:298), [unbounded cache](/Users/ramon/src/quickwit/quickwit/quickwit-search/src/leaf.rs:715), [accounting](/Users/ramon/src/quickwit/quickwit/quickwit-search/src/leaf.rs:855), [overshoot contract](/Users/ramon/src/quickwit/quickwit/quickwit-search/src/search_permit_provider.rs:205).
- **Concurrent publication:** objects are uploaded before publication. The inspected PostgreSQL metastore publishes new splits and marks replaced splits for deletion in a transaction. This is metadata-service coordination, not S3-only CAS. Sources: [uploader](/Users/ramon/src/quickwit/quickwit/quickwit-indexing/src/actors/uploader.rs:348), [publication](/Users/ramon/src/quickwit/quickwit/quickwit-metastore/src/metastore/postgres/metastore.rs:784).
- **Retention:** queries select published splits; old immutable objects remain available for a deletion grace period, 32 minutes by default. Inference: a finite grace period cannot by itself protect indefinitely mounted historical revisions. Gat needs durable reachability/retention or a defined lease policy for its search blocks. Sources: [split selection](/Users/ramon/src/quickwit/quickwit/quickwit-search/src/lib.rs:242), [grace period](/Users/ramon/src/quickwit/quickwit/quickwit-common/src/shared_consts.rs:24).
- **Regex semantics:** regex queries operate over indexed terms and warm matching postings. This does not directly implement Git regex matching over original source lines. Sources: [regex construction](/Users/ramon/src/quickwit/quickwit/quickwit-query/src/query_ast/regex_query.rs:133), [postings warmup](/Users/ramon/src/quickwit/quickwit/quickwit-search/src/leaf.rs:541).

Borrow the bundle offsets, footer-first opening, immutable segments, and batched range reads. For gat, replace unbounded warmup with bounded streaming of posting blocks and original blobs.

## Implications for gat

The following is a proposed design, not an implemented feature:

1. Preserve the existing exact grep matcher and output path. Add an index that conservatively identifies candidate blob IDs, then verify candidates against original bytes. Indexing must never discard a real match. The current implementation walks selected trees and reads file contents: [grep](/Users/ramon/src/gat/internal/repo/view_objects.go:593).
2. Investigate byte-trigram postings, keyed by immutable blob IDs so identical contents across paths and commits share indexing work. Intersect candidates with the selected tree and its pathspec. A revision-to-blob membership/path mapping needs its own bounded, persistent representation; do not build a repository-wide in-memory map on every query.
3. Store immutable, independently addressable posting blocks plus small routing metadata. Use protobuf for structured metadata and the existing ranged `Store.Get` for fetching blocks. The existing store already provides byte ranges and atomic conditional publication: [store contract](/Users/ramon/src/gat/internal/store/store.go:15).
4. Put index roots and explicit coverage/version information in the same immutable publication reached through gat's CAS-updated HEAD. Pin that publication once per query. If a revision or blob is outside index coverage, scan it; incomplete indexing must not produce false negatives. Retain blocks needed by supported historical revisions and active readers.
5. Budget resident cache bytes, temporary decoded blocks, postings iterators, and concurrent fetches separately. A 32 MiB cache is not a 32 MiB process RSS promise. Admission must reserve bytes before reads; bounded streaming is preferable to preloading every posting needed by a broad query.
6. Extract only provably required trigrams from literals/regexes. Short patterns, broad expressions, inversion, and case-folding rules require conservative handling or a streaming fallback. A common query such as `the` may still select most files; an index alone does not guarantee a subsecond result.

## Proposed measurement gate

Before adopting a search library, benchmark a range-backed prototype against the existing scan on the reusable medium fixture:

- Compare outputs and exit status against native Git for the supported option set, including historical versions, multiple selectors, path filtering, binary inputs, case-insensitive matches, and patterns with no useful trigrams.
- Measure rare literals, common literals, missing literals, selective regexes, and unselective regexes. Include concurrent readers and an import while readers remain pinned to an older publication.
- Record cold application-cache and warm-cache wall time, GET count, bytes downloaded, peak resident cache, temporary allocations/RSS, import time, and index size. Local FS, latency-injected local storage, and real S3 are distinct measurements; do not present one as the other.
- Flag every measured operation over one second. Compare alternative posting block sizes and concurrency with identical cache limits; verify that no hidden whole-segment download occurs.

No engine was built or benchmarked as part of this source inspection.
